# Как устроен провайдер

Провайдер — это одна область хоста: репозитории, хранилища, гости. Всё, что
от него требуется, — ответить на два вопроса.

```go
type Provider interface {
    ID() string          // "host/storage" — попадает в план и в --only
    Title() string       // одна строка для дерева на экране
    Describe() string    // что делает и чего не делает, человеческим языком

    Configured(m *manifest.Manifest) bool
    Plan(ctx, m, f) (plan.Changes, error)
    Verify(ctx, m, f) ([]plan.Finding, error)
}
```

## Главное правило

**Провайдер ничего не выполняет.** Он возвращает список шагов, а исполняет их
движок — показывая команду или diff до того, как она случится, снимая копию
файла и записывая всё в лог.

```go
func (s Storage) Plan(_ context.Context, m *manifest.Manifest, f *facts.Facts) (plan.Changes, error) {
    var out plan.Changes
    out.Steps = append(out.Steps, plan.Step{
        ID:       "host/storage:content:local",
        Provider: s.ID(),
        Resource: "хранилище local",
        Summary:  "добавить content: snippets",
        Action:   plan.ActionExec,
        Cmd:      []string{"pvesm", "set", "local", "--content", "backup,iso,snippets"},
    })
    return out, nil
}
```

В bash-версии это было устроено иначе: `mod_check` печатал, что собирается
сделать, а `mod_apply` делал это заново. Те же ветвления, написанные дважды, и
ни одной гарантии, что второй раз получится то же самое.

Обойти ворота нельзя. `internal/provider/guard_test.go` разбирает дерево кода
и падает, если в провайдер пробрался `os/exec` или запись в файл. Проверку не
обойти ни переносом строки, ни переменной с именем команды.

**Если страж упал — не добавляй исключение.** Опиши изменение шагом плана.

## Правило нуля

`Configured` отвечает на вопрос «описана ли эта область в манифесте вообще».
Ложь значит: провайдер не сделает ничего, и это норма, а не ошибка и не «уже в
порядке». На экране у таких областей свой значок — неприметная точка.

Отличать «не настроено» от «уже в порядке» обязательно. Слить их вместе значит
скрыть от человека, что он забыл ключ.

## Три вида ответа

| Что | Когда | Как выглядит |
|---|---|---|
| `Steps` | есть что менять | `→` в дереве, попадает в план |
| пусто | состояние уже такое, как описано | `✓` |
| `Notes` | keel видит расхождение, но исправить его не может | `!` рядом с областью |

Заметка — не изменение. Хранилище типа LVM keel не заведёт: решать это за
человека слишком опасно. Он скажет об этом и пройдёт мимо, а план не будет
обещать того, чего применение не сделает.

## Откуда берутся данные

Провайдер не ходит в файловую систему и не запускает команд. Всё, что он знает
о хосте, приходит в `*facts.Facts` — и собирает их `internal/facts`, один раз
на запуск.

Нужен новый факт — добавь его туда. Это не бюрократия: из-за этого правила
провайдеры проверяются без хоста, без сети и без root, обычными тестами.

## Условия перед шагом

Иногда проверять надо не при сборке плана, а прямо перед выполнением. Связь
до репозитория — как раз такой случай: между просмотром плана и применением
проходит время, и связь за это время меняется.

```go
step.Guards = []plan.Guard{{
    Kind: plan.GuardNetSpeed,
    Arg:  "30K",
    Why:  "связь до репозитория не медленнее 30K/с",
}}
```

Условие не выполнилось — шаг не начат, и это не сбой: keel отказался
начинать, и хост остался цел.

## Секреты

Значений секретов в плане нет и быть не может: план лежит на диске обычным
файлом. В шаг кладётся метка, а подставляет её тот, кто выполняет шаг, —
прямо перед выполнением и только в памяти.

```go
fmt.Fprintf(&b, "printf '%%s:%%s' 'av' '%s' | chpasswd\n", secret.Mark("102"))
step.SecretRefs = []string{"102"}
```

Спрашиваются секреты **до** сборки плана (`App.Prepare`). Применение должно
идти без остановок, иначе план не артефакт, а обещание.

## Порядок и зависимости

Порядок применения задаёт реестр в `internal/cli/app.go`: хранилища заводятся
раньше гостей, которые на них лягут. Внутри провайдера порядок задаётся полем
`Needs`.

```go
// Заводить хранилище, каталог которого не создался, незачем:
// pvesm его примет, а работать оно не будет.
Needs: []string{mkdirID},
```

Шаг, который ждал упавшего, не выполняется. Это важнее, чем кажется: поставить
обновления, список которых не обновился, — не то же самое, что не ставить их
вовсе.

## Тесты

Провайдер проверяется сверкой собранных команд — дословной. Это место, где
живёт большинство ошибок.

```go
func TestStorageAddsMissingContent(t *testing.T) {
    c := planOf(t, parse(t, `{"storages":[{"name":"local","content":["snippets"]}]}`), hostWithStorages())
    assertCommands(t, commands(c.Steps), []string{
        "pvesm set local --content backup,iso,snippets,vztmpl",
    })
}
```

Отдельно стоит проверить три вещи, которые ломаются чаще всего: правило нуля,
поведение с существующим объектом (его нельзя трогать) и то, что объект вне
манифеста не попал ни в одну команду.
