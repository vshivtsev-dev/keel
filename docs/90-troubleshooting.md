# Если что-то пошло не так

## Сначала — три команды

```bash
keel logs                       # полный вывод последнего запуска
keel doctor                     # что за хост и в каком он состоянии
ls /root/keel/backups/       # копии файлов, снятые до каждой правки
```

Перед любой правкой файла keel кладёт его копию в
`/root/keel/backups/<дата>/<путь>`. Вернуть как было — обычный `cp`.

---

## «Не найден Perl с модулем JSON::PP»

Читать манифест нечем. На нормальном Proxmox такого быть не должно — Perl там
есть всегда, сам PVE на нём написан.

```bash
apt install --reinstall perl-modules-5.36   # номер версии подставь свой
```

## Комментарии в манифесте ломают разбор

`keel doctor` покажет, в каком режиме работает парсер. Если написано, что
`relaxed` недоступен — keel срезает комментарии запасным способом, и это
штатное поведение. Если ошибка всё же есть, сузь до строки:

```bash
keel validate
```

## apt update ругается на 401 от enterprise.proxmox.com

Это ровно то, что чинит модуль репозиториев:

```bash
keel plan --only host/10-repos
keel apply --only host/10-repos
```

## «Ни у одного хранилища не разрешены сниппеты»

ВМ из облачного образа без них не настроить. Добавь `snippets` в `content`
хранилища `local`:

```jsonc
"storages": [
  { "name": "local", "content": ["iso", "vztmpl", "backup", "snippets"] }
]
```

и примени `host/30-storage`.

## Гость не создался: «storage does not exist»

Имя хранилища в манифесте не совпадает с тем, что на хосте. Установщик
Proxmox заводит `local-lvm` при установке на LVM и `local-zfs` при установке
на ZFS. Посмотреть, что есть:

```bash
pvesm status
```

и поправить `storage` у гостя.

## Диск не расширился до нужного размера

`qm resize` не умеет уменьшать. Если в манифесте размер меньше, чем у
исходного образа, keel предупредит и оставит ВМ как есть — это не ошибка
создания, гость уже рабочий.

## В контейнере нет ускорения, glxinfo показывает llvmpipe

По порядку:

1. `keel doctor` — есть ли на хосте `/dev/dri`? Нет — видеокарту не подхватил
   драйвер хоста, до контейнера дело не дошло.
2. Внутри контейнера: `ls -l /dev/dri` — устройства должны быть видны.
3. `id` внутри контейнера — пользователь должен состоять в группе, которой
   принадлежат устройства. keel настраивает это сам, но если контейнер
   создавался руками — проверь.

## xrdp подключается и сразу отключается

Классика: пользователь уже вошёл в сессию локально, либо не хватает
`dbus-x11`. Внутри контейнера:

```bash
systemctl restart xrdp
journalctl -u xrdp -n 50
```

## Задание резервного копирования не создаётся

Если `pvesh create /cluster/backup` ругается на отсутствующий параметр `id` —
версия Proxmox старше, чем ожидалось, и требует задавать идентификатор
задания явно. Заведи задание один раз через веб-интерфейс (Датацентр →
Резервные копии), поставь в поле «Комментарий» слово `keel` — дальше keel
подхватит его и будет поддерживать в описанном состоянии сам.

## Пароль от рабочего стола потерялся

```bash
keel password 101
```

Если файла нет — пароль задавался вручную при создании. Сменить изнутри:

```bash
pct exec 101 -- passwd av
```

## keel отказывается обновляться: «скорость до репозитория мало»

keel измеряет связь до репозитория перед закачкой и не начинает обновление,
если она слишком медленная. Это не придирчивость: на медленной или
обрывающейся сети apt складывает не стартовавшие закачки обратно в очередь и
пробует снова. На сотне пакетов очередь растёт быстрее, чем что-либо
скачивается, и `apt-get` способен съесть всю память хоста — однажды так и
вышло, 6.4 ГБ из 11.

Первым делом проверь IPv6 — это самая частая причина:

```bash
keel doctor | grep -A2 IPv6
```

Если keel пишет, что DNS отдаёт AAAA, а маршрута нет, то половина попыток apt
уходит в «Network is unreachable», и каждая ждёт таймаута. Лечится одной
строкой:

```bash
echo 'Acquire::ForceIPv4 "true";' > /etc/apt/apt.conf.d/99force-ipv4
apt-get update
```

Дальше проверь сам канал:

```bash
curl -4 -so /dev/null -w 'IPv4: %{speed_download} B/s\n' \
  http://deb.debian.org/debian/dists/trixie/Release
```

Десятки килобайт в секунду — обновление лучше отложить до починки сети.
Мегабайты — повтори `keel apply --only host/20-updates`.

Если скорость честно низкая, но обновиться надо прямо сейчас и ты готов
приглядывать за памятью, порог снимается в манифесте:

```jsonc
"host": { "updates": true, "updates_min_speed": "0" }
```

Тогда следи за `free -h` в соседнем окне и будь готов прибить `apt-get`, пока
не проснулся OOM-killer. Убивать безопасно, пока `pgrep -a dpkg` пуст.

## Признаки, что apt уже захлебнулся

```
W: Tried to start delayed item http://… but failed
```

Много таких строк подряд — это и есть растущая очередь закачек. Вместе с ними
обычно видно `Cannot initiate the connection … Network is unreachable` и
скорость в единицы килобайт в секунду. Прерывай, пока память цела:

```bash
pgrep -a dpkg          # пусто — распаковки нет, прерывать безопасно
kill <pid apt-get>
free -h                # память должна вернуться сразу
```

База пакетов при этом не страдает: пока dpkg не начал распаковку, apt только
качает.

## Скачивание образа обрывается

Образы кэшируются в `/root/keel/images`. Недокачанный файл останется там и
помешает повторной попытке — удали его и запусти снова:

```bash
rm /root/keel/images/имя-файла
keel apply --only guests/50-guests
```

## keel говорит «Это не хост Proxmox VE»

Защита от запуска не на той машине. Если ты точно понимаешь, что делаешь:

```bash
KEEL_ALLOW_NON_PVE=1 keel apply
```

## Что-то применилось не так, как хотелось

```bash
ls -la /root/keel/backups/          # выбрать нужную дату
cp /root/keel/backups/2026-09-15_030000/etc/network/interfaces /etc/network/interfaces
```

Резервные копии снимаются автоматически перед каждой правкой файла, без
отдельного разрешения — это не изменение системы, а страховка.
