# Рабочий стол на Proxmox

Как получить графическую машину на хосте со встроенной видеокартой — и почему
основной путь именно такой.

## Три варианта и почему выбран первый

Железо, под которое это писалось: Radeon 780M в APU Ryzen 7 8745HS —
**единственная видеокарта в машине**. Отсюда всё и следует.

| | **A. LXC + /dev/dri** | **B. ВМ + virtio-gl** | **C. Полный проброс** |
|---|---|---|---|
| 3D (OpenGL) | ~нативно | грубо 20–50% | 95–99% |
| Vulkan | да | нет | да |
| Аппаратное декодирование видео | да | нет, декод на CPU | да |
| Изоляция | общее ядро с хостом | полная | полная |
| Хост теряет монитор | нет | нет | **да, навсегда** |
| Риск для хоста | низкий | низкий | высокий |
| Откат | мгновенный | мгновенный | правка загрузчика + перезагрузка |
| Подключение | RDP | SPICE | физический монитор или SPICE |

Цифры — порядки величин из общей литературы, а не замеры этой машины.

**Выбран A.** Контейнер делит встроенную видеокарту с хостом: работает и 3D,
и аппаратное декодирование видео, при этом хост не теряет консоль. У 780M
известная беда с пробросом — так называемый reset bug: после выключения ВМ
карта не освобождается, и лечится это только перезагрузкой хоста. В варианте
A этой проблемы не существует как класса.

**B** остаётся доступным одной строкой в манифесте — для случая, когда нужна
именно настоящая ВМ с отдельным ядром.

**C** [припаркован](BACKLOG.md).

## Как включить

```jsonc
{
  "id": 101,
  "name": "desktop",
  "profile": "desktop",
  "graphics": "dri",        // контейнер; "virgl" — виртуальная машина
  "cores": 4,
  "memory": 8192,
  "disk": "64G",
  "cloudinit": { "user": "alex", "ssh_key_from": "host" },
  "packages": ["keepassxc", "remmina"]
}
```

`profile: "desktop"` — это роль. Чем её закрыть, решает `graphics`: keel сам
выберет профиль `desktop-lxc` или `desktop-vm`.

## Что внутри получается

**Вариант A (контейнер):** Ubuntu 24.04, XFCE, xrdp, PipeWire, Firefox, VLC,
`vainfo` для проверки аппаратного декодирования. Устройства `/dev/dri`
проброшены с хоста.

**Вариант B (ВМ):** то же самое плюс `spice-vdagent` и звуковое устройство
на стороне Proxmox — без него гость просто не увидит звуковую карту, сколько
пакетов внутрь ни ставь.

## Как подключаться

**К контейнеру — по RDP.** Любой RDP-клиент: Подключение к удалённому
рабочему столу в Windows, Remmina в Linux, Microsoft Remote Desktop на Mac.
Адрес контейнера, пользователь из манифеста.

Пароль keel спрашивает при создании. Если создавал в неинтерактивном режиме
(`--yes`) — пароль сгенерирован и лежит здесь:

```bash
keel password 101
```

**К виртуальной машине — по SPICE.** Нужен клиент `virt-viewer`. В
веб-интерфейсе Proxmox: Console → SPICE, скачивается файл, открывается
virt-viewer. Через обычную веб-консоль (noVNC) не будет ни звука, ни
ускорения — это ограничение noVNC, а не настройки.

## Права на видеокарту: почему это не болит

Внутри контейнера номер группы, владеющей `/dev/dri`, отличается от хостового
и зависит от дистрибутива: в Ubuntu `render` это 993, в Debian — 104. Угадать
нельзя, а ошибка даёт неработающее ускорение без единого сообщения об ошибке.

Поэтому keel не угадывает: сценарий первичной настройки смотрит, какой группе
устройство досталось на самом деле, при необходимости создаёт группу с таким
номером и добавляет в неё пользователя. Если поменяется дистрибутив или
версия — ничего править не придётся.

## Проверить, что ускорение работает

Внутри контейнера или ВМ:

```bash
glxinfo | grep "OpenGL renderer"   # должен быть AMD, а не llvmpipe
vainfo                             # список профилей — аппаратный декод жив
```

`llvmpipe` в выводе означает программную отрисовку: видеокарта не досталась.
Смотри `keel doctor` — есть ли на хосте `/dev/dri`.

## Если Proxmox старше 8.2

Ключи `dev0`, `dev1` для проброса устройств в контейнер появились в 8.2. На
более старых версиях keel честно откажется, а сделать то же самое руками
можно так — в `/etc/pve/lxc/<id>.conf`:

```
lxc.cgroup2.devices.allow: c 226:* rwm
lxc.mount.entry: /dev/dri dev/dri none bind,optional,create=dir
```

После правки контейнер нужно перезапустить. Для непривилегированного
контейнера дополнительно понадобится сопоставление групп (`lxc.idmap`), и
именно поэтому keel этот путь не автоматизирует: слишком много зависит от
конкретной системы, а ошибка молча ломает изоляцию.
