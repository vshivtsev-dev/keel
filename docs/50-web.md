# Веб-интерфейс

`keel web` поднимает на самом хосте небольшой HTTP-сервер и показывает в
браузере то же, что показывает терминал: план, поток применения, состояние
хоста. Это другой экран для того же keel, а не вторая его версия.

```bash
keel web
```

```
keel web
Адрес: http://127.0.0.1:8777/?t=3895K6zOYxxUYpEfLkySBDGNNl38F77f
  Токен лежит в /root/keel/secrets/web.txt — тот же адрес можно собрать заново.
  Слушаю только этот хост. С ноутбука — через туннель:
    ssh -N -L 8777:127.0.0.1:8777 root@адрес-хоста
  Остановить — Ctrl+C.
```

## Как попасть на страницу с ноутбука

По умолчанию сервер слушает только `127.0.0.1`, поэтому с другой машины
нужен туннель. Он же заодно даёт шифрование, которого у самого сервера нет:

```bash
ssh -N -L 8777:127.0.0.1:8777 root@адрес-хоста
```

Дальше открываешь на ноутбуке тот адрес, который keel напечатал на хосте, —
вместе с `?t=…`. После первого открытия токен уезжает в куку, и адрес можно
сокращать до `http://127.0.0.1:8777/`.

Открыть порт наружу можно (`keel web --listen 0.0.0.0`), но keel об этом
предупредит, и правильно сделает: страница работает под root и меняет хост,
а HTTP здесь без шифрования. В общей сети так делать не стоит.

## Что можно и чего нельзя

| Кнопка | Что делает | Меняет хост |
|---|---|---|
| План | `keel plan` | нет |
| Проверка | `keel verify` | нет |
| Состояние | `keel doctor` | нет |
| Гости | `keel guests` | нет |
| Применить план | `keel apply --yes` | **да** |

Кнопка применения не работает, пока не нажат «План»: соглашаться можно
только с тем, что прочитал. Это то же самое одно согласие, что и в терминале,
просто взятое мышью, — поэтому keel на той стороне и запускается с `--yes`.

Одновременно применять нельзя: на время работы появляется файл-замок
`/root/keel/web-apply.lock`, и вторая вкладка получит отказ. Если замок
остался от прерванного запуска, удали его руками.

## Чего веб-интерфейс не умеет

Это не «пока не сделано», а следствие устройства — читай до того, как
понадеешься.

**Не работает при восстановлении с нуля.** Пока Proxmox не установлен и не
загрузился, поднимать HTTP-сервер негде. Восстановление идёт из консоли, по
[docs/00-RECOVERY.md](00-RECOVERY.md), и так будет всегда.

**Не спрашивает пароли и токены.** Применение идёт в режиме `--yes`, а он по
определению не задаёт вопросов. Значит:

- пароль гостя будет **сгенерирован** и сохранён в `/root/keel/secrets/<id>.txt`
  (посмотреть: `keel password 101`);
- токен внешнего сервиса keel придумать не может, поэтому гость, которому он
  нужен, **не создастся**. Положи токен заранее — например,
  `/root/keel/secrets/cloudflared.txt`, — и повтори. Подробности:
  [docs/40-cloudflared.md](40-cloudflared.md).

**Нет пошагового режима.** `--step` остаётся терминальным: вопрос перед каждым
изменением — это диалог, а страница показывает поток.

**Закрытая вкладка ничего не останавливает.** keel работает на хосте, а не в
браузере. Кнопка «Остановить чтение» прекращает показ, но не применение.
Остановить само применение можно там, где запущен `keel web`, — Ctrl+C.

## Устройство

Сервер — `lib/web.pl`, чуть больше четырёхсот строк вместе с комментариями.
Из модулей только те, что входят в стандартную поставку Perl и потому есть
на любом Proxmox: `IO::Socket::INET`, `JSON::PP`, `Digest::SHA`, `POSIX`,
`Fcntl`. Ничего не ставится и не качается — то же правило, что и у остального
keel: инструмент восстановления, который перед работой требует `apt install`,
плохой инструмент восстановления.

Страница (`web/`) не содержит логики о хосте. Она отправляет ровно два
намерения — «покажи» и «применяй» — и рисует то, что прислал keel. Правило
нуля, порядок модулей, отказ применять вне Proxmox живут в одном месте, в
самом keel: второй экземпляр этих правил однажды разошёлся бы с первым.

Каждое соединение обслуживает отдельный процесс. Это не про нагрузку:
применение идёт минутами, и всё это время сервер обязан отвечать другим
вкладкам.

## Токен

Лежит в `/root/keel/secrets/web.txt` с правами 0600, переживает перезапуск
сервера. Без него сервер не отвечает ничего — в том числе на `127.0.0.1`:
на хосте бывают и другие пользователи, а этот сервер работает под root.

Сменить — удалить файл и запустить `keel web` заново:

```bash
rm /root/keel/secrets/web.txt
keel web
```
